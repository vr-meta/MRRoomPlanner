# CLAUDE.md — правила работы над проектом

**Обязательно:** вести работу строго по чек-листу — [`docs/CHECKLIST.md`](docs/CHECKLIST.md).

## Правила

1. Перед началом задачи — свериться с `docs/CHECKLIST.md`: что уже сделано, что нет.
2. Держать чек-лист в актуальном состоянии: `[x]` выполнено, `[~]` в работе, `[ ]` не начато.
3. Если задача начата, но не завершена — **разбить её на под-задачи** и отмечать их по
   мере готовности. Не оставлять крупную задачу «наполовину» без декомпозиции.
4. Технические/архитектурные решения — в [`docs/design/`](docs/design/README.md). При
   реализации следовать им; при изменении решения — обновлять соответствующий документ.
5. **Решённые проблемы окружения фиксировать** в чек-листе (раздел «Решённые проблемы»),
   чтобы не наступать на них повторно.
6. **Соблюдать свод правил кода** — [`docs/design/12-coding-rules.md`](docs/design/12-coding-rules.md)
   (winding наружу, `IsAlive` вместо null-проверок интерфейсных ссылок, удаления через
   команды, ноль аллокаций в кадре, тесты к новой логике).
7. **Любая новая фича/инструмент/крупный рефакторинг — строго по скиллу `/new-feature`**
   (`.claude/skills/new-feature/SKILL.md`): сначала дизайн-док и декомпозиция в чек-листе,
   затем код по правилам, headless-проверка (`driver.mjs test All` + `setup` при смене
   состава рига), синхронизация доков, коммит только на зелёных тестах.
8. **Любое меню/панель/виджет — строго по дизайн-коду UI**
   [`docs/design/20-ui-design-system.md`](docs/design/20-ui-design-system.md):
   настройки инструмента — только через `SettingsSchema` v2 (Stepper/Slider/Segmented/
   Select/Toggle/Numeric/Swatch/Action/Readout/Progress/Header; суб-режимы — **Tabs**,
   `Cycle` запрещён), цвета — только токены `Core/UiTokens` (hue = слоям данных,
   состояния — яркостью, деструктив — Danger + hold 0.5 с), иконки — SVG-пути в
   `Core/IconPaths.cs` (24×24, заливки, evenodd; каждая новая — с тестом),
   переключение инструментов — радиал (слот-таблица в `ToolManager`; 12 позиций
   зафиксированы навсегда, новые инструменты — в резервные слоты или табом).
   Анти-паттерны из §7 дока — обязательные запреты.

## О проекте

MR-приложение для Meta Quest 3/3S (Horizon OS): скан помещения и работа с интерьером —
рулетка, покраска/текстуры, стены, проёмы, мебель через AI, инженерные сети, обмен
форматами (IFC/DWG/glTF). Клиент — Unity 6 (6000.0.81f1) + C#; база — сэмпл **Virtual
Home** (MRUK). Верхнеуровневая карта — [`ARCHITECTURE.md`](ARCHITECTURE.md).

## Карта кнопок

Раскладка ввода (триггер/грип/стик/кнопки, свободные слоты) — [`docs/design/10-controls.md`](docs/design/10-controls.md).
При изменении управления обновлять этот документ.

## Язык и тесты

- **Код и UI — на английском** (идентификаторы, комментарии, лейблы меню, единицы «cm»).
  Ответы в чате — по-русски.
- Чистую, независимую от устройства логику держим в сборке **`RoomPlanner.Core`**
  (`Assets/RoomPlanner/Scripts/Core`, asmdef без Meta/TMP) — она юнит-тестируема.
- Тесты — **EditMode** в `Assets/RoomPlanner/Tests` (`RoomPlanner.Tests` asmdef → ссылается на
  `RoomPlanner.Core`). Новую логику покрывать тестами; запуск через Window → General → Test Runner.

## Сквозной принцип

Геометрия и отделка — **параметрические данные**, меши/материалы генерируются
процедурно. Без CSG-объединений и «запечённых» развёрток. См. `docs/design/00-overview.md`.

## Пересборка и прогон тестов (важно) — делает Claude сам, headless

**Правило: Claude запускает тесты и Setup сам, без участия пользователя.** Всё работает
через Unity batchmode, поэтому **редактор Unity должен быть ЗАКРЫТ** (batchmode берёт лок
проекта; при открытом редакторе скрипты выходят с понятной ошибкой).

| Что нужно | Команда |
|---|---|
| Прогнать все тесты | `powershell -File ci/run-tests.ps1 -Mode All` |
| Только EditMode / PlayMode | `... -Mode EditMode` / `-Mode PlayMode` |
| Пересобрать риг (бывш. RoomPlanner → Setup Measure Rig) | `powershell -File ci/unity-run.ps1 -Method RoomPlanner.EditorTools.CiTools.SetupRig` |
| Собрать APK | `powershell -File ci/unity-run.ps1 -Method RoomPlanner.EditorTools.CiTools.BuildAndroid -TimeoutMin 30` |

Скрипты печатают итог (`total/passed/failed`, имена упавших тестов) и отдают ненулевой
exit code при проблемах. Артефакты (`TestResults-*.xml`, `ci-*.log`, `Build/`) — в `.gitignore`.

Когда что нужно:
- Изменена **только логика** внутри существующих скриптов → достаточно пересборки/`BuildAndroid`.
- Изменён **состав рига** (новые компоненты/сериализованные поля/префабы) → сначала **SetupRig**,
  потом сборка. Просто сборка **не дозаполняет** новые сериализованные поля в объекте сцены.
- После правок логики — **прогонять тесты** (`ci/run-tests.ps1`) до отчёта пользователю.
- Проверка, что новый билд доехал: в `adb logcat` строка вида `[Measure] vN started ... contBtn=True`.

Если редактор открыт и его закрыть нельзя — попросить пользователя закрыть его либо
запустить нужный пункт руками из меню/Test Runner.

## Окружение (Windows)

- Диск **C: почти полон — всё ставить на D:**:
  - редакторы Unity — `D:\Unity\Editors`
  - инсталляторы — `D:\Installers`
  - TEMP для установок — `D:\Temp`
- Unity Hub — MSIX (виртуализирует TEMP на C:), поэтому редакторы ставим **офлайн-
  инсталляторами** Unity, а не через Hub. Детали — в `docs/CHECKLIST.md` → «Решённые проблемы».
