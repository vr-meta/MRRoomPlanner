# Свод правил и требований к коду

Выведен из аудита 2026-08-09 (`docs/AUDIT-2026-08-09-PLAN.md`) и внесённых исправлений.
Правила обязательны для нового кода и при правках существующего. Каждое правило родилось
из реального бага — в скобках ссылка на первоисточник.

## 1. Процедурная геометрия

1.1. **Все треугольники мешей — наружу.** MeshCollider-рейкаст видит только фронтальные
     грани; вывернутая грань смещает точку пика на толщину элемента — для приложения с
     точностью «cm» это функциональный баг, а не косметика. Комментарий «у нас двусторонний
     материал, winding не важен» — запрещён. (Floor/Wall, аудит WP2)

1.2. **Каждый новый тип геометрии — с тестом на нормали.** Ассерты знака нормали для
     каждой грани (`Cross(v1-v0, v2-v0)`), плюс PlayMode-ассерт точки хита на ожидаемой
     грани с малым допуском. Расширять допуск теста, чтобы «прошло», нельзя — допуск
     маскировал вывернутый пол.

1.3. **Геометрия обязана переживать «грязный» ввод MR-контроллера**: дубль-клики
     (схлопывать соседние точки ближе 1 мм), развороты ~180° (miter limit, фолбэк
     нормали), отрицательные параметры (нормализовать через `Abs` + минимум). Молчаливая
     деградация в мусорную геометрию запрещена. (Wall.BuildFootprint)

1.4. **Публичный `Build(...)` не доверяет входу**: null-guard и защита от алиасинга
     (вход может быть собственным внутренним списком объекта — очистка до копирования
     стирает вход). (Wall.Build / Points)

1.5. **Каждый `new Mesh` / `new Texture2D` имеет владельца и точку освобождения.**
     `Destroy(gameObject)` НЕ освобождает меши и текстуры — обязателен `OnDestroy`
     (с веткой `DestroyImmediate` для Editor) либо `Destroy(old)` при замене.
     (Wall/Floor meshes, план пола)

## 2. Время жизни объектов (Unity)

2.1. **Интерфейсная ссылка на MonoBehaviour не проверяется через `!= null`.**
     Перегруженный `==` UnityEngine.Object не работает через интерфейс — уничтоженный
     компонент проходит проверку и падает при обращении. Правило: у интерфейса есть
     `bool IsAlive` (реализация `this != null` в компоненте), и любой потребитель
     проверяет `x != null && x.IsAlive`. (ISelectable, краш Undo)

2.2. **Единственный владелец времени жизни — `SceneModel` + история.** Удаление для
     пользователя = `DeleteCommand` (скрытие, отменяемо). Жёсткий `Destroy` разрешён
     только для: незавершённых заготовок (превью, недостроенная цепочка) и вытеснения по
     лимиту — и всегда через `SceneModel.Unregister` ДО `Destroy`.

2.3. **`SceneModel.Unregister` обязан чистить историю** от команд с этой целью
     (`ISelectableCommand.Target`). Иначе Undo реанимирует мертвеца. Страховка:
     `Selectable.OnDestroy` сам вызывает `Unregister` через `SceneModel.Instance`.

2.4. **Скрытое ≠ живое.** Всё, что итерирует объекты сцены (снапы, магниты, дедуп
     маркеров, лимиты, «удалить последний»), обязано фильтровать скрытые
     (`activeSelf`/`IsHidden`): невидимая стена не должна магнитить курсор, скрытое
     измерение — считаться «последним» для удаления.

## 3. Undo/Redo

3.1. **История exception-safe**: команда снимается со стека только ПОСЛЕ успешного
     вызова (`Peek → вызов → Pop`); упавший `Do()` не попадает в историю.

3.2. **Команды безопасны на мёртвой цели** — no-op, не исключение (см. 2.1).

3.3. **Никакого неучтённого дрейфа.** Любое живое изменение (драг) при завершении —
     в том числе при смене инструмента или блокировке меню — либо записывается командой,
     либо полностью откатывается. «Осталось применённым, но не в истории» запрещено.

3.4. **Undo/Redo заблокированы, пока идёт драг** — реплей истории посреди накопления
     дельты рассинхронизирует итоговую команду.

## 4. Производительность (Quest, 72–120 Гц)

4.1. **Ноль аллокаций в пер-кадровых путях** (`Tick`/`Update`/`LateUpdate`):
     `Physics.RaycastNonAlloc` с кэшированным буфером вместо `RaycastAll`; `GetComponent`
     — кэшировать; LINQ/`new List` в кадре — нельзя.

4.2. **Драг — это transform-превью + одна пересборка на отпускании.** Полный rebuild
     параметрической геометрии с перепеканием MeshCollider каждый кадр запрещён.
     Паттерн: во время драга `Transform.position += delta`; в конце — откат превью и
     единичный `MoveBy(total)` + запись команды.

4.3. **Текст/TMP обновлять только при смене значения.** Кэшировать последнюю строку;
     `ForceMeshUpdate` — только после фактической смены текста. Строки в кадре не
     форматировать без изменения данных.

4.4. **Хаптика и прочие «хвосты» гасятся в `OnDisable`.**

## 5. Ввод и UI

5.1. **Видимая панель полностью блокирует сцену.** У фоновых квадов панелей есть
     коллайдеры (слой 2); «дырки» между кнопками, сквозь которые триггер ставит точки
     на стену позади, запрещены.

5.2. **Жест с удержанием не должен перехватываться другим действием.** Захват панели —
     только по фронту нажатия грипа над ней (`GetDown`), а не по уже удерживаемому грипу
     снапа, задевшему панель лучом.

5.3. **Всё выключенное на время операции — восстанавливается при любом выходе** из
     операции, включая `OnDeactivate` (коллайдеры точек при драге, hover-состояния).

5.4. **Фолбэк-значения не участвуют в дельтах.** Курсор драга инициализируется только
     реальным пересечением с плоскостью; «точка на 2 м вдоль луча» как база для дельты
     даёт телепорт объекта.

## 5a. Setup-код и рантайм

5a.1. **Нельзя назначать рантайм-делегаты (`MenuButton.OnClick` и подобные) из
     `Editor/Setup`.** Setup выполняется в редакторе и сохраняет СЦЕНУ; лямбда в сцену не
     сериализуется, поэтому в билде обработчик пуст — кнопка выглядит рабочей и молчит.
     Действие кнопки, создаваемой Setup'ом, — только сериализуемое (`MenuAction` +
     индекс/параметр в полях). Делегаты — для кнопок, которые строит рантайм-код
     (`InspectorPanel`). (Вкладки полоски снапов, фидбек 2026-08-15: «переключение вкладок
     не работает»)

## 6. Тесты и процесс

6.1. **Новая логика — с тестами; исправленный баг — с регрессионным тестом.** EditMode
     для чистой геометрии/математики, PlayMode для физики/пикинга/команд.

6.2. **Тестировать реальные компоненты, а не рукописные дубли**, как только границы
     сборок позволяют. Дубли (`FakeSelectable`/`GeoProbe`) дрейфуют от оригинала.

6.3. **Прогон тестов — до отчёта пользователю**: `node .claude/skills/run-mrroomplanner/driver.mjs test`
     (редактор открыт → мост; закрыт → batchmode) либо `powershell -File ci/run-tests.ps1 -Mode All`.

6.4. **Editor-тулинг не пересоздаёт ассеты.** `AssetDatabase.CreateAsset` — только если
     ассета нет; существующий ассет мутировать (GUID сохраняется, внешние ссылки живут).

6.5. Чек-лист (`docs/CHECKLIST.md`) и дизайн-доки обновляются вместе с кодом; изменение
     раскладки ввода — синхронно в `docs/design/10-controls.md`.
