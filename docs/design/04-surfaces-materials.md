# 04 — Отделка: поверхности и материалы (Surfaces & Materials) 🔜

> **Состояние (базовый слой реализован):** метрические UV генерируются при построении меша —
> у стен (`u` вдоль стены, `v` от низа) и у боков/низа плиты пола; шаг плитки `TileMeters = 1 м`
> (`Wall.TileMeters`, `Floor.TileMeters`). Материал по умолчанию — **процедурный бесшовный бетон**
> (`Surface_ConcreteTex`, генерируется в `SetupAssets`; бинарных ассетов в репозитории нет).
> Стены больше не полупрозрачно-голубые.
>
> **Верх плиты пола — поверхность чертежа**, а не отделки: его UV задаёт `BlueprintPlacement`, и
> `BlueprintController` кладёт туда `plan.png`. Бетон там — лишь вид по умолчанию, пока плана нет.
> Чтобы бетон и чертёж жили одновременно, план надо вынести отдельным слоем-калькой над плитой —
> решение за потоком Blueprint, см. [17-floor-outline](17-floor-outline.md).
>
> **Покраска v1 реализована** (I14): инструмент **Paint («Pnt»)** — луч на свою
> стену/пол/лестницу + триггер красит объект в текущий цвет (цикл-ряд «Color»,
> 8 пресетов в `Tools/PaintController`); ряд «Original look» снимает краску с объекта
> под прицелом. Краска — состояние `Selectable` (`SetPaint/ClearPaint/IsPainted`),
> визуал — один писатель `ApplyVisual`: property block на **материал 0** тела
> (стекло/столярка не тонируются), подсветка hover/selected лерпит от цвета краски и
> восстанавливает её, а не материал (P1.4). Каждый мазок — `PaintCommand` (undo
> восстанавливает прежний цвет, включая «не покрашено»). Там же — тумблеры **Vertex AO**
> (пересборка всех мешей) и **SSAO** (renderer feature).
>
> Примечание (2026-08-10): в `worktree-electrical` параллельно была сделана вторая
> реализация покраски (только стены, MPB в `Wall`); при merge принята версия main
> как более полная, дубль удалён.
>
> Ещё не сделано: origin и поворот UV, зоны (`SurfaceRegion`), **разные цвета у двух

## Текстуры v1 (2026-08-10, ветка `worktree-work3`)

Реальные **CC0-текстуры с ambientCG** (лицензия позволяет вшивать в APK без
атрибуции). Бинарники в репозиторий НЕ коммитятся: editor-меню
**RoomPlanner → Download Textures** скачивает курируемый набор в
`Assets/RoomPlanner/Textures/` (в `.gitignore`); повторный запуск — идемпотентен,
SetupRig падает с понятной ошибкой, если набор не скачан.

**Курируемый набор** (1K JPG, только Color-карта в v1):

| Категория | AssetId | tile, м |
|---|---|---|
| Обои (стены) | Wallpaper001A, Wallpaper001C, Wallpaper002A, Wallpaper002B | 1.0 |
| Крашеная стена | PaintedPlaster001, PaintedPlaster006, PaintedPlaster010, PaintedPlaster017 | 1.5 |
| Пол (паркет/ламинат) | WoodFloor051 (ёлочка), WoodFloor040, WoodFloor007, WoodFloor064 | 2.0 |

**Модель отделки** — расширение краски, та же машинерия `Selectable`:

```csharp
// Core: чистые данные
struct SurfaceFinish { FinishKind Kind;   // None | Color | Texture
                       Color Color;       // Color-режим И тинт поверх текстуры
                       string TextureId;  // ключ каталога ("wallpaper-001a")
                       float TileMeters;  // тайл по U (горизонталь/X), м
                       float TileMetersY; } // тайл по V; 0 = квадрат (= TileMeters)
// FinishLibrary (MonoBehaviour на риге): id → Texture2D + tileMeters + категория;
// Setup wired из скачанных ассетов. Текстуры уезжают в APK через ссылки компонента.
```

- Применение — **MPB**: `_BaseMap/_MainTex` + `_BaseMap_ST = (1/tileX, 1/tileY, 0, 0)`
  на материал 0 (body-only, как краска); цвет = тинт (`_BaseColor`), по умолчанию
  белый. Материалы не мутируются; hover/selected лерпает поверх — `ApplyVisual`
  остаётся единственным писателем. Панель Paint даёт степперы Tile W/H (стены) и
  Tile X/Z (полы), ±25 см, 25–800 см; «auto» = тайл из каталога (фидбек 2026-08-11).
- **Undo**: `PaintCommand` расширяется до before/after `SurfaceFinish` (не дельта).
- **Верх плиты пола (T4, реализовано 2026-08-11)** — ДВА UV-канала: `uv0` — проекция
  чертежа (план выравнивается между плитами, как раньше), `uv1` — метрический мировой
  XZ. Шейдер `LitVertexAO` получил `_UseUV1`; `Selectable` включает его через MPB
  только для полов с текстурной отделкой. План и текстура не конфликтуют.
- **Развёртка торцов/верха стен (2026-08-11)**: cap-грани и верх/низ стены получают
  собственные вершины с метрической развёрткой (U вдоль, V поперёк толщины в метрах) —
  прежде UV были вырождены и текстура мазалась полосами. Оба пути триангуляции
  (обычный и с проёмами), включая откосы и коробки joinery. Тест `MetricUvTests`:
  UV-площадь каждого треугольника == мировой площади (метрическая развёртка 1:1).
- **Персист**: `ProjectData` — к цвету добавляются `finishKind/textureId/tile`.
- **UI (по дизайн-коду 20)**: панель Paint получает **Tabs**: Color (сетка 8 цветов,
  как сейчас) / **Walls** (свотчи обоев+штукатурок) / **Floors** (свотчи паркетов).
  Текстурный свотч = плашка с самой текстурой (MPB). Триггер по поверхности —
  применить активную отделку; Original look работает для любой отделки.

Осознанно отложено: Normal/Roughness-карты (v1 — только Color, unlit-подобный вид
как у краски), свой tileMeters per-поверхность в UI, зоны.

## Единая развёртка = метрические UV (мировой масштаб)

Не делать авто-развёртку каждого меша отдельно (даёт разный масштаб). Единое правило:

```
UV = (позиция_на_поверхности_в_метрах) / размер_плитки_в_метрах
```

- Стена: `u` = длина вдоль стены (м), `v` = высота от пола (м).
- Пол/потолок: `u,v` = координаты в плоскости пола (м).
- Делим на `tileSizeMeters` (0.3 для плитки 30 см; ширина рулона обоев и т.п.).

Результат: **1 м реального мира = фиксированный кусок текстуры** на любой поверхности
любого размера. Плитка 30×30 везде одинакова. UV генерируем процедурно при построении
меша. Дополнительно — **origin и поворот UV** на поверхность:
- швы плитки/старт обоев привязаны к углу/полу;
- переключатель «рисунок непрерывный через угол (общий origin)» ↔ «свой на поверхность».

Для органических материалов (штукатурка/бетон) — опционально **triplanar-шейдер**
(масштаб автоматически одинаковый, без швов; но точную сетку плитки лучше метрическими UV).

## Двусторонние стены

Передняя и задняя грань стены — отдельные полигоны, у каждого **свой материал и своя
UV-привязка** (комната A / комната B). Backface culling → каждая сторона показывает своё.

## Части поверхности разного цвета/текстуры

- **v1 — параметрические прямоугольные зоны** (`SurfaceRegion`, submesh): панели,
  акценты, зона плитки, разные высоты. Чётко, точно, редактируемо. Используют то же
  метрическое UV.
- **v2 — покраска маской** (splat/paint в render texture): свободная кисть; тяжелее по
  памяти. Каналы RGBA = до 4 материалов на маску.

## Пол — зоны

Пол делим на зоны (прямоугольники/полигоны) → submesh со своим материалом и **тем же
метрическим UV** (паркет/плитка совпадают по масштабу). Origin общий (стыки совпадают)
или свой на зону.

## Скелет и производительность (Quest)

```csharp
class Surface       { Material baseMaterial; float tileSizeMeters; Vector2 uvOrigin; float uvRotation;
                      List<SurfaceRegion> regions; }
class WallFace : Surface { }              // одна сторона стены
class SurfaceRegion { Rect areaMeters; Material material; /* tileSize/origin опц. переопределяются */ }
// WallSegment: WallFace sideA, sideB;
```

Производительность: батчинг по материалу; **texture arrays/атлас** + GPU instancing
(draw calls критичны для 90 fps); разумное число уникальных материалов (библиотека);
мипмапы + анизотропия; **Passthrough Relighting** для вписывания в реальный свет.
