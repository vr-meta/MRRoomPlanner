# 04 — Отделка: поверхности и материалы (Surfaces & Materials) 🔜

> **Состояние (базовый слой реализован):** метрические UV генерируются при построении меша —
> у стен (`u` вдоль стены, `v` от низа) и у боков/низа плиты пола; шаг плитки `TileMeters = 1 м`
> (`Wall.TileMeters`, `Floor.TileMeters`). Материал по умолчанию — **процедурный бесшовный бетон**
> (`Surface_ConcreteTex`, генерируется в `SetupAssets`; бинарных ассетов в репозитории нет).
> Стены больше не полупрозрачно-голубые.
>
> **Верх плиты пола — поверхность чертежа**, а не отделки: его UV задаёт `BlueprintPlacement`, и
> `BlueprintController` кладёт туда `plan.png`. Бетон там — лишь вид по умолчанию, пока плана нет.
> Чтобы бетон и чертёж жили одновременно, план надо вынести отдельным слоем-калькой над плитой —
> решение за потоком Blueprint, см. [17-floor-outline](17-floor-outline.md).
>
> Ещё не сделано: `tileSizeMeters` за материал/поверхность, origin и поворот UV, зоны
> (`SurfaceRegion`), разные материалы у двух сторон стены.

## Единая развёртка = метрические UV (мировой масштаб)

Не делать авто-развёртку каждого меша отдельно (даёт разный масштаб). Единое правило:

```
UV = (позиция_на_поверхности_в_метрах) / размер_плитки_в_метрах
```

- Стена: `u` = длина вдоль стены (м), `v` = высота от пола (м).
- Пол/потолок: `u,v` = координаты в плоскости пола (м).
- Делим на `tileSizeMeters` (0.3 для плитки 30 см; ширина рулона обоев и т.п.).

Результат: **1 м реального мира = фиксированный кусок текстуры** на любой поверхности
любого размера. Плитка 30×30 везде одинакова. UV генерируем процедурно при построении
меша. Дополнительно — **origin и поворот UV** на поверхность:
- швы плитки/старт обоев привязаны к углу/полу;
- переключатель «рисунок непрерывный через угол (общий origin)» ↔ «свой на поверхность».

Для органических материалов (штукатурка/бетон) — опционально **triplanar-шейдер**
(масштаб автоматически одинаковый, без швов; но точную сетку плитки лучше метрическими UV).

## Двусторонние стены

Передняя и задняя грань стены — отдельные полигоны, у каждого **свой материал и своя
UV-привязка** (комната A / комната B). Backface culling → каждая сторона показывает своё.

## Части поверхности разного цвета/текстуры

- **v1 — параметрические прямоугольные зоны** (`SurfaceRegion`, submesh): панели,
  акценты, зона плитки, разные высоты. Чётко, точно, редактируемо. Используют то же
  метрическое UV.
- **v2 — покраска маской** (splat/paint в render texture): свободная кисть; тяжелее по
  памяти. Каналы RGBA = до 4 материалов на маску.

## Пол — зоны

Пол делим на зоны (прямоугольники/полигоны) → submesh со своим материалом и **тем же
метрическим UV** (паркет/плитка совпадают по масштабу). Origin общий (стыки совпадают)
или свой на зону.

## Скелет и производительность (Quest)

```csharp
class Surface       { Material baseMaterial; float tileSizeMeters; Vector2 uvOrigin; float uvRotation;
                      List<SurfaceRegion> regions; }
class WallFace : Surface { }              // одна сторона стены
class SurfaceRegion { Rect areaMeters; Material material; /* tileSize/origin опц. переопределяются */ }
// WallSegment: WallFace sideA, sideB;
```

Производительность: батчинг по материалу; **texture arrays/атлас** + GPU instancing
(draw calls критичны для 90 fps); разумное число уникальных материалов (библиотека);
мипмапы + анизотропия; **Passthrough Relighting** для вписывания в реальный свет.
