# 18 — Импорт IFC (Revit → редактируемая модель) 🔜

Конкретизация [08-interop](08-interop.md) до реализуемого MVP. Ветка: `worktree-ifc-import`.

**Цель:** принести проект из Revit (экспорт в IFC) в шлем и получить **редактируемые
параметрические** стены/полы нашей модели — не «немой меш». Дальше пользователь
докрашивает/двигает/достраивает обычными инструментами.

## Референс-файл

`Project1.ifc` (Revit 24.2, IFC2X3, мм, 10 МБ, ~206k сущностей) — реальный жилой дом:

| Сущность | Кол-во | Использование |
|---|---|---|
| `IfcWallStandardCase` | 41 | все с представлением `Axis` (`IfcPolyline`, 2 точки) + толщина из `IfcMaterialLayer` + высота из `IfcExtrudedAreaSolid` |
| `IfcColumn` | 31 | все прямоугольные 300×300 (`IfcRectangleProfileDef` + экструзия) |
| `IfcSlab` | 11 | профиль контура (`IfcArbitraryClosedProfileDef`/`IfcRectangleProfileDef`) + толщина |
| `IfcBuildingStorey` | 5 | отметки уровней (0 / 3150 / 6100 / 9050 / 11300) |
| `IfcDoor` / `IfcWindow` / `IfcOpeningElement` | 17/16/36 | размеры прямо в сущности; связи `IfcRelVoidsElement`/`IfcRelFillsElement` |
| `IfcFurnishingElement` | 21 | Brep-меши (IKEA), имена в типе |
| `IfcFlowTerminal` | 21 | сантехника (кириллица в `\X2\…\X0\`) |
| `IfcSpace` | 0 | Revit не экспортировал комнаты (настройка экспорта) |

## Решения

1. **Свой лёгкий парсер STEP-подмножества в `RoomPlanner.Core`**, без Xbim:
   - Xbim на IL2CPP/Android — риск (reflection, вес); наше подмножество — ~15 типов сущностей.
   - Парсер = текстовый формат ISO-10303-21: `#id=TYPE(arg,arg,…);`, аргументы —
     строки/числа/enum `.X.`/ссылки `#n`/вложенные списки. Полностью юнит-тестируемо.
   - Никакого бэкенда: 10 МБ текста на устройстве парсится за секунды; строим индекс
     `id → сырая запись`, разрешаем ссылки лениво только для нужных типов.
2. **Импорт на устройстве**: `.ifc` кладётся в `Download` (как планы Blueprint),
   выбор файла — тот же паттерн `PlanFileLocator` (расширим до generic-локатора).
3. **Маппинг (MVP):**
   | IFC | → Наша модель |
   |---|---|
   | `IfcBuildingStorey.Elevation` | уровни (Level) этажей |
   | `IfcWallStandardCase` `Axis` + `IfcMaterialLayerSetUsage` (толщина) + экструзия (высота) | `Wall` (лента, 2-точечная осевая) |
   | `IfcColumn` с `IfcRectangleProfileDef` | **короткий сегмент `Wall`** (ось = длинная сторона профиля через центр, толщина = короткая) — красится/выбирается как стена, нового типа объекта нет |
   | `IfcSlab` (профиль контура) | `Floor.BuildOutline` + толщина; `IfcOpeningElement` на плите / внутренние контуры профиля → `Floor.AddHole` |
   | `IfcDoor`/`IfcWindow` через `IfcOpeningElement` (RelVoids/RelFills) | `WallOpening` на сегменте графа → панелизация v0 в `Wall.BuildSegment` (простенки/перемычка/откосы; окна — стекло сабмешем 1 + рама, двери — рама + полотно, сабмеш 2 `Wall_Joinery`). **Двери с известным свингом рендерятся приоткрытыми на 75°** (проход свободен): петля и сторона — из `IfcDoorStyle.OperationType` (SINGLE_SWING_LEFT/RIGHT) + осей размещения двери (зеркальные экземпляры Revit кодирует отрицательными осями — учитывается само); `SwingDir`/`HingeDir` — мировые направления на `WallOpening`, ноль = закрытое полотно (нарисованные руками двери) |
   | `IfcStairFlight` (подступёнки/проступи; Revit пишет размеры в футах) | параметрический `Stair` (Core), три типа: Solid (клин до земли) / Open (ступени на косоурах) / **Waist (марш-плита «как в подъезде»: ступени поверх наклонной плиты постоянной толщины, снизу ровный скошенный потолок, у верха вертикальный срез)**; ширина/направление — из bbox Brep-точек; ступени — цель телепорта. **Импорт по умолчанию делает Waist** (фидбек 2026-08-10); в `ProjectStair` тип хранится как `Kind:int` (legacy `Open:bool` читается при `Kind = -1`) |
   | `IfcSlab .LANDING.` (межмаршевые площадки, Brep без экструзии) | `Floor` через **верхнюю грань оболочки Brep** (кольцо точек на максимальном Z; толщина = высота всей оболочки — низ у монолитных площадок скошен). Этаж — наследуется от родительской `IfcStair` через `IfcRelAggregates` (марши и площадки не лежат в контейнере этажа) |
   | `IfcFlowTerminal` (сантехприборы) / `IfcFurnishingElement` (мебель) / `IfcBuildingElementProxy` (душевые, декор) / `IfcRailing` (перила) | запечённые меши (`MepView` + `MepCategory`, вершины локально вокруг origin), материал по категории (фаянс/дерево/пластик/металл); **цвет и прозрачность из `IfcStyledItem`** (→ `Selectable.SetPaint`, прозрачные ≥0.3 получают стеклянный материал); 2D-прокси (аннотации) пропускаются со счётчиком; трубы/электрика — только когда есть в экспорте |
   - Проёмы в MVP **не вырезаем** (модуль Openings не готов) — стены сплошные; данные
     дверей/окон в файле полные, подключим Фазой D.
4. **Координаты:** мм → м (×0.001); IFC right-handed Z-up → Unity Y-up:
   `(x, y, z) → (x, z, y)`. Позиции элементов — композиция цепочки `IfcLocalPlacement`
   (элемент → этаж → здание → площадка); 2D-точки `Axis` поднимаются через неё в мир.
5. **Импорт = команды**: элементы рождаются через `SceneModel`/`EditHistory` одной
   составной командой — весь импорт отменяется одним Undo.
6. **Навигация по дому (телепорт)** — в MR камеру не двигаем (passthrough):
   двигаем **модель относительно пользователя**. Кнопка **A** (глобально): луч в точку
   любой плиты → `TeleportCommand` сдвигает модель так, что точка оказывается у ног;
   прицел в плиту верхнего этажа опускает его до реального пола — это и есть смена этажа.
   Реализация — сдвиг **данных** (каждый узел графа один раз + контуры всех плит, включая
   скрытые), а не общего трансформа `Building`: узлы графа хранят мировые координаты, и
   трансформ-родитель молча рассинхронизировал бы их с миром. Отменяемо (X).
   Математика — `Core/BuildingNav.TeleportDelta`. Фильтр видимости этажей — ряд Storey
   инструмента Import.

## Скелет классов

```
Core/Ifc/StepTokenizer.cs   — разбор одной записи: id, тип, дерево аргументов
                              (строки с \X2\-юникодом, числа, .ENUM., #ref, $, *, списки)
Core/Ifc/StepFile.cs        — построчный ридер файла → индекс id→запись (лениво парсим аргументы)
Core/Ifc/IfcImporter.cs     — обход: Storeys / Walls (axis+thickness+height+placement) /
                              Columns (rect) / Slabs (outline) → ImportedBuilding
Core/Ifc/ImportedBuilding.cs— чистые данные: ImportedStorey/ImportedWall/ImportedSlab (метры, Unity-оси)
Core/BuildingNav.cs         — математика телепорта (смещение корня, выбор видимого этажа)
Import/ImportController.cs  — ITool "Imp": ряды IFC file (листать) / Load / Storey (фильтр
                              видимости по этажам); строит сегменты WallGraph (Offset=Center)
                              + Floor через FloorController.CreateImported; один Undo
                              (ImportBatchCommand: hide/show всего созданного)
Editor/Setup/SetupImportTool.cs + строка в реестре ToolManager.Start + SetupPalette
```

## Покрытие v2 (2026-08-11, по анализу сэмплов youshengCode/IfcSampleFiles)

Инструмент анализа — `RoomPlanner → Analyze IFC Samples` (`IfcAnalyzer`, headless
через `ci/unity-run.ps1 -Method RoomPlanner.EditorTools.IfcAnalyzer.Analyze`):
по каждому файлу из `TestData/ifc` печатает импортировано/пропущено/неподдержанные
типы. Изменения покрытия:

- **BakedTypes расширен**: IFC4-переименования (`IfcFurniture`, `IfcSanitaryTerminal`)
  и «показать хотя бы мешем» — `IfcFlowController` (выключатели), `IfcFlowMovingDevice`,
  `IfcEnergyConversionDevice`, `IfcCovering`, `IfcBeam`, `IfcMember`, `IfcPlate`,
  `IfcCurtainWall`, `IfcRoof`.
- **Фолбэк-бейк**: стены без Axis-полилинии или без параметрической высоты и
  непараметрические лестничные марши больше не пропадают — бейкаются Proxy-мешем
  (`BakeProduct`, общий с MEP-петлёй). Заморожённый меш лучше дыры в доме;
  редактируемость — только у параметрического пути.
- Не покрыто и осознанно: `IfcSpace` (не геометрия — пригодится для комнат, док 09),
  `IfcFooting` (фундаменты под землёй), 2D-аннотации (`IfcGeometricSet`).

## Осознанно откладываем

- **Вырез дверей/окон в меше стены** — Фаза D (панелизация, док 03); импорт уже кладёт
  их как `WallOpening`-данные на сегменты графа (мировые экстенты углов профиля проёма →
  along/width/height/sill), так что при появлении панелизации они отрисуются сами.
  Тогда же: прозрачные стёкла у окон (материал панели остекления), открывающиеся двери
  (створка = отдельный подвешенный меш).
- **Лестницы параметрически** (I9): `IfcStairFlight` несёт числа подступёнков/проступей
  и их размеры (внимание: Revit пишет RiserHeight/TreadLength в ФУТАХ независимо от
  единиц файла) — делаем свой Core-модуль Stair с процедурными ступенями, Brep-меш
  из IFC не тащим. Площадки (`IfcSlab .LANDING.`, Brep-only) импортируются как плиты
  через верхнюю грань оболочки — см. маппинг выше.
- Навигация стиком и «виртуальная земля» (VR-фон) — I10, вопрос дизайна: непрерывный
  сдвиг данных = пере-меш каждый кадр (запрещено правилами перфоманса), альтернатива —
  сдвиг trackingSpace, но он рвёт инвариант «мир = реальная комната».
- Круглые колонны (`IfcCircleProfileDef`) — MVP пропускает с пометкой в статусе импорта.
- `IfcSpace` (в референс-файле не экспортированы), сетки осей `IfcGrid`, дуговые стены
  (`IfcTrimmedCurve`) — позже по мере надобности.
- Round-trip (экспорт обратно в IFC) — после формата проекта (док 06).
- IFC4 (пока только IFC2X3 — то, что даёт Revit по умолчанию в CoordinationView).

## Тестовая стратегия

- Юнит-тесты токенизатора/ридера — на инлайн-фрагментах STEP.
- Тесты `IfcImporter` — на **мини-fixture** (несколько КБ), собранной из реальных цепочек
  `Project1.ifc` (стена #150 со всеми зависимостями, колонна #277, слэб #236, этажи) —
  кладётся в `Tests/Fixtures/`. Сам 10-МБ файл в репозиторий не кладём.
- Play-тесты: Load fixture → в сцене N стен/полов, undo снимает всё одной командой.

## Маркер места импорта (#60, фидбек 2026-08-13)

Триггер в инструменте Import ставит **маркер цели** (кольцо Ø0.7 м) на поверхность под
лучом — скан, свои стены/полы (слой 6, двойной рейкаст как у электрики; ближайший хит
побеждает). «Load IFC» сажает здание **нижним центром футпринта** (`Core/Ifc/
ImportPlacement`: XZ-центр bounds стен и плит, Y = низшая база — низ плиты первого
этажа) точно в отмеченную точку: `MoveTo = Translate(target − Anchor)`, сдвигаются все
мировые данные (пути стен + BaseHeight, контуры/дыры/Level плит, базы лестниц, Origin
MEP, Elevation этажей), относительные — нет (доли проёмов, локальные вершины MEP).

- **B** — сначала снимает маркер, потом обычный Esc в Select.
- Без маркера — прежнее поведение (координаты файла как есть).
- **Загрузка проекта маркер игнорирует**: IFC идёт через `LoadBuilding` (смещение),
  проект — напрямую `BuildScene`; сохранённая сцена никогда не пере-смещается
  (play-тест `ImportMarkerPlayTests`).

## Электрика из IFC: розетки → нативные фикстуры (#79, 2026-08-15)

Revit экспортирует розетки как `IfcBuildingElementProxy` с крошечным mapped-телом
(плашка 5×5×1 см) и говорящим именем («Р Розетка:220 V»; выключатели/светильники в
CoordinationView не экспортируются вовсе — 2D-аннотации Revit не переживают экспорт).
Вместо немого Proxy-меша импортёр распознаёт их (`Core/Ifc/ElectricalImport.IsOutlet`,
регистронезависимо: «розетк»/outlet/socket) и кладёт в `ImportedBuilding.Outlets`
(позиция = центр bbox, нормаль = тончайшая ось плашки — `PlateNormal`).

`ImportController.SpawnImportedOutlets` превращает их в **настоящие** `ElectricFixture`
через фабрику персиста (`ElectricController.RestoreFixture`) — импортированная розетка
неотличима от поставленной руками: редактируется (посты/высота), принимает провода,
попадает в смету щитка и в сохранение проекта. Ориентация: тонкая ось плашки со знаком
ОТ ближайшей осевой линии стены (лицом в комнату); лежачая плашка (ось Y) — напольная
коробка. Повторный Load заменяет их вместе со всей электрикой (`ClearElectrical`).
Порты `IfcDistributionPort` (33 шт. в референс-файле) пока не используются — задел
для авто-трассировки.

## Материалы предметов (2026-08-16, issue #124 → `29-object-materials.md`)

Запечённый элемент больше **не одноцветный**: `BrepWorldMesh` записывает span
треугольников на каждый геометрический item, `BakeProduct` сливает их по стилю в
`ImportedMep.Parts` (контигуальные диапазоны `TriStart/TriCount` поверх общего списка
вершин), а сцена строит по сабмешу и материалу на часть. У предметов без
`IfcStyledItem` имя и цвет берутся из материала — `IfcRelAssociatesMaterial` напрямую и
через `IfcRelDefinesByType`, цвет — из `IfcMaterialDefinitionRepresentation`. Плюс
метрические box-UV (`Core/BoxUv`), без которых текстурная отделка на импорт не ложится,
и подбор отделки по имени материала (`Core/Ifc/IfcMaterialMap`). Замеры на реальном
экспорте и таблица «имя → отделка» — в `29-object-materials.md`.
