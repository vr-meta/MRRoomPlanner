# 19 — Электрика: розетки, выключатели, провода, щиток 🔜

Первая реализация слоя `Electrical` из [07-mep-layers](07-mep-layers.md). UX выработан
панелью из трёх экспертов (VR-моторика · инженер-электрик · MR/HCI), 2026-08-10.
Принцип прежний: **всё — параметрические данные**, меши генерируются процедурно.

## Модель данных (Core)

```csharp
enum FixtureKind { Outlet, Switch, Panel }
enum CableType   { C3x15, C3x25 }            // "3x1.5" (свет), "3x2.5" (розетки)

// ElectricFixture : MonoBehaviour (Core, как Wall/Floor — тестируемо)
//   Kind, Posts (1..5, Outlet), Keys (1..3, Switch); позиция/ориентация — transform
//   (стоит на грани стены, yaw по нормали). Build() — процедурный меш, winding наружу.
//   TerminalWorld — точка ввода кабеля (центр верха блока; у щитка — низ).

// WireRoute : MonoBehaviour (Core)
//   Points (List<Vector3>, мировые, лежат на поверхностях), CableType,
//   StartFixtureId / EndFixtureId (логическая связь, string Id из SceneModel),
//   Build() — трубка Ø15 мм вдоль ломаной (8-гранник, winding наружу), Length.

// WireMath (static): OrthoWaypoints(prev, next, runY) — вертикаль → горизонталь на
//   высоте прокладки → вертикаль (схлопывание вырожденных колен < 1 см);
//   PolylineLength; BuildTube(points, radius, sides, mesh-листы).

// ElectricalBom (static): смета по списку трасс:
//   Σ длины по CableType + 0.15 м × кол-во подключений (привязанные концы)
//   + общий запас % → строки "3x1.5 — 24.6 m", "Total — 62.7 m".
```

Щиток — тоже `ElectricFixture` (Kind=Panel, 300×400×80 мм), **один на сцену в v1**.
Смету он собирает не по проводке ссылок, а **через реестр `SceneModel`** (все живые
нескрытые `WireRoute`) — как `WallController` находит плиты пола (паттерн C5).

## UX (сведённые решения панели)

- **Один инструмент «Elec»** (7-я кнопка палитры), суб-режимы — первый ряд инспектора:
  `Mode: Outlet → Switch → Wire → Panel` (Cycle). Акцент слоя `UiColors.LayerElectrical`
  #FFC94D — ретикл/кромки, но **не сами объекты**: провода графит #1A1A1A (чистый чёрный
  на passthrough «дыра»), розетки/выключатели/щиток — белые.
- **Фикстуры**: луч + триггер по грани стены (промах/пол = отказ + хаптика; «воздушных»
  точек нет). Высота **жёстко снапится к пресету** (Outlet 30 см, Switch 90 см,
  Panel 150 см до центра — от `Level`), грип во время постановки = свободная вертикаль.
  Превью — ghost-блок на стене. Подстройка высоты — степпером в инспекторе, не жестом
  (тремор луча ±3–5 см > шага степпера).
- **Провод**: точка за точкой триггером по стенам и потолку. Режим **Ortho** (дефолт):
  между кликами вставляются колени — вертикаль → горизонталь на «высоте прокладки»
  (**отступ от потолка**, ряд `Ceiling off`, дефолт 20 см; потолок = `Level + WallHeight`
  либо фактический Y точки) → вертикаль. Free — прямые сегменты. Углы комнаты пользователь
  проходит кликом на угол (v1; авто-излом по общему ребру — v2).
  **Завершение — B** (как FinishChain у Walls); **клик по щитку завершает трассу сам**.
  Конец/начало ближе 10 см к терминалу фикстуры — снап (квадратный ретикл) + запись
  логической связи: фикстура двигается — привязанный конец едет за ней.
  Дефолт кабеля от стартовой фикстуры: от Switch — 3x1.5, от Outlet — 3x2.5.
- **Щиток и смета**: метраж — в `Describe()` выбранного щитка (группа выделения
  инспектора): строки по типам кабеля + Total с запасами. Ряд `Reserve %` (0–30, шаг 5)
  — per-instance. Формула: Σ длин + 0.15 м × подключение + запас %.
- **Настройки инструмента** (дефолты для следующих объектов):
  Outlet: `Posts 1..5`, `Height см`; Switch: `Keys 1..3`, `Height см`;
  Wire: `Cable 3x1.5↔3x2.5`, `Route Ortho↔Free`, `Ceiling off см`; Panel: `Reserve %`.
  Per-instance те же ряды через `ISettingsProvider` выбранного объекта.
- **Редактирование v1**: через Select — фикстуру тащить (стандартный драг), B — удалить
  (DeleteCommand); у трассы `EditHandle`-ручки на точках (`RouteHandles : IHandleProvider`,
  один жест = одна команда). Смена суб-режима/инструмента с начатой трассой ≥2 точек —
  **авто-финиш**, не потеря.
- **Защита от грязного ввода**: дебаунс точки 250 мс + мин. шаг 3 см; пересечение
  габаритов фикстур (порог 5 см) — отказ; B по пустоте при рисовании = финиш трассы,
  Esc-семантика — со второго B.

Классификация поверхности под лучом — **по нормали хита** (`|n.y|<0.3` стена,
`n.y<-0.7` потолок, иначе отказ): работает и по EffectMesh скана, и по своим стенам.

## Осознанно отложено (v2)

- Светильники, распаячные коробки, слаботочка; несколько щитков; автоматы/номиналы.
- Авто-излом орто-сегмента по общему ребру смежных стен; прокладка по полу.
- Re-host фикстуры на другую стену; вставка точки в середину трассы; ветвление.
- Снап к проёмам (выключатель у наличника) — после интеграции openings.
- Layer-чипы палитры (eye/solo) — вместе со вторым MEP-слоем; экспорт сметы (08-interop).
- Перемещение щитка (в v1 — удалить и поставить заново).

## Интеграция с main (2026-08-10, после мерджа v1)

Фидбек первой примерки в шлеме — три стыка с системами main, починены на стороне main:

- **Телепорт**: `TeleportCommand` теперь сдвигает и электрику (фикстуры `MoveBy` +
  `BaseLevel += delta.y`, чтобы высоты «над этажом» пережили вертикальный телепорт;
  трассы `MoveBy` целиком — привязанные концы не двигаются дважды). Без этого розетки
  и провода визуально «ехали вместе с пользователем».
- **Сброс проекта**: `ImportController.ClearScene` («New project») уничтожает
  ЗАРЕГИСТРИРОВАННЫЕ в `SceneModel` фикстуры/трассы; припаркованный шаблон префаба и
  ghost-превью инструмента не зарегистрированы и переживают сброс.
- **Реальный потолок**: `CeilingY()` больше не берёт `manager.Level + WallHeight`
  (высота ИНСТРУМЕНТА стен, 2.7 м — в импортированном доме потолки 3 м+). Теперь —
  луч вверх с высоты колена в XZ точки: ближайшая грань «смотрящая вниз» не ниже 2 м
  над полом (низ мебели отсекается порогом, свои трассы/ручки — фильтром по
  `WireRoute`); фолбэк — прежняя формула. Отступ трассы от потолка остаётся
  настройкой «Ceiling off» (10–50 см, по умолчанию 20).
