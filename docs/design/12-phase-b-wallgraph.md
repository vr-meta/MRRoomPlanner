# 12 — Фаза B: WallGraph и правка стен (план внедрения)

Это **план работ**, а не дизайн. Модель узлов/сегментов задана в
[02-walls](02-walls.md), место фазы в роадмапе — в [11-object-operations](11-object-operations.md)
(§3.2, §3.3, Фаза B). Здесь — как это внедрить пошагово, не ломая работающее.

Фундамент выбора (Фаза A) готов: `SceneModel`, `Selectable`, `SelectController`,
`EditHistory` (X/Y), команды Move/Delete. Тесты — 45/45 зелёные.

## Цель фазы

1. Стены живут в **графе** (узлы + сегменты), а не как независимые полилинии.
2. **Общий узел**: тянешь угол — двигаются все примыкающие стены. T-стыки настоящие.
3. **Тянуть вершины** ручками, с undo.
4. Толщина/высота/offset/join — **за экземпляр**, а не только глобальные дефолты.
5. Привязки вынесены в единый `SnapService`.

## Принципы, которые нельзя нарушить

- Параметры → процедурный меш, **без CSG** (`00-overview`).
- После каждого шага: **приложение работает**, тесты зелёные. Не оставляем «полуграф».
- Чистая логика — в `RoomPlanner.Core` / `RoomPlanner.Editing` (юнит-тестируемо),
  MonoBehaviour-обвязка — тонкая.
- Порядок шагов подобран так, что визуал не регрессирует: сначала данные, потом рендер,
  потом UI.

### B2 — Построение меша сегмента с учётом соседей
Сейчас `Wall.Build()` строит **полилинию** целиком, и join считается внутри неё. Для
per-instance параметров и проёмов нужен билд **одного сегмента**, а стык — из графа.
- [ ] Вынести из `Wall.cs` расчёт поперечников в чистую функцию: вход — направление сегмента,
      его толщина/offset и направления соседей в каждом узле; выход — 4 точки подошвы + join-точки
- [ ] Стык в узле: 2 сегмента → miter/bevel/round (как сейчас); 3+ (T) → срез по каждому соседу;
      1 (тупик) → торцевая заглушка
- [ ] Тесты: прямой сегмент · L-угол (miter совпадает с текущей геометрией) · T-стык (3 сегмента) ·
      тупик · разная толщина у соседей
- Файлы: `Core/WallMesh.cs` (новый), `Core/Wall.cs` (становится рендерером сегмента)
- SetupRig: **не нужен** (пока не переключили контроллер)
- ⚠️ Риск регресса углов — поэтому тест «L-угол даёт ту же геометрию, что сейчас» пишем **до** правки

## Риски

| Риск | Митигация |
|---|---|
| Регресс геометрии углов при переходе на per-segment | Тест «L-угол = текущая геометрия» пишем **до** рефактора (B2) |
| Много `MeshCollider` (сегмент вместо цепочки) | Мерить на устройстве; при просадке — один коллайдер на цепочку/чанк |
| Порядок обхода узла даёт «вывернутый» стык | Сортировать соседей по азимуту в узле; тест на T-стык |
| Двойное владение объектами (долг Фазы A) | Закрывается в B3, отдельным пунктом |

## Порядок и зависимости

```
B1 (данные) → B2 (меш) → B3 (переключение) → B4 (параметры) → B5 (ручки)
                                    ↘ B6 (SnapService, можно параллельно после B3)
                                                                  ↘ B7 (задел)
```

Минимально ценный результат для пользователя достигается на **B5**: «выбрать стену → потянуть
вершину → соседние стены поехали → undo». B1–B3 — невидимый пользователю фундамент, поэтому их
делаем быстро и подряд.
