# 06 — Формат проекта и переносимость (Project I/O) 🔜

## Реализовано: v1 (персистентность v0, 2026-08-10)

- **`Core/Project/ProjectData`** — JSON (JsonUtility): версия схемы, узлы графа стен +
  сегменты (толщина/высота/BaseHeight/Offset/Join/SideSign + проёмы along/w/h/sill),
  контуры полов с дырками (`ProjectRing`-обёртки — JsonUtility не умеет вложенные
  списки), лестницы (параметры + тип Solid/Open), placement чертежа. **Только
  параметры, мешей нет** — геометрия перегенерируется при загрузке. Единственное
  исключение — импортированные MEP-меши (у них параметров не существует).
- **`Import/ProjectStore`** — Capture (сцена → данные; скрытые/удалённые не пишутся)
  и Apply (очистка сцены → `ImportController.BuildScene`: загрузка идёт тем же
  конвейером, что импорт IFC).
- **`Import/ProjectAutosave`** — автосейв в `autosave.rp.json` (папка приложения) на
  `OnApplicationPause`/`Quit` (на Quest пауза = выход), автозагрузка на старте.
  Пустая сцена файл не перетирает. Кнопок нет — комната «просто остаётся».
## Реализовано: Проекты v1 (инструмент Projects, issue #58, 2026-08-13)

- **`Core/Project/ProjectCatalog`** — чистые правила имён (юнит-тесты): на Quest нет
  клавиатуры, имена генерируются — «Project N» с наименьшим свободным N (удалённый
  слот переиспользуется); маппинг имя↔файл `<name>.rp.json`; numeric-aware порядок
  списка («Project 2» раньше «Project 10»); `autosave` — зарезервированное имя.
- **`Import/ProjectPaths`** — именованные проекты в `<persistentDataPath>/projects/`;
  текущий проект — в PlayerPrefs (`rp.currentProject`, пишется сразу — Quest убивает
  приложения молча); пустое имя = безымянная сцена на легаси-`autosave.rp.json`.
- **`Import/ProjectsController`** (инструмент «Proj», слот радиала бывшего Heating):
  Readout текущего, Select-список (открытый помечен «•»), **Open** (сначала автосейв
  текущей сцены — переключение не теряет работу), **Save** (первое сохранение
  безымянной сцены выделяет «Project N»; пустая сцена имя не выделяет), **New**
  (деструктив: чистая безымянная сцена, именованные файлы не трогает), **Delete**
  (деструктив: файл+бэкап; удаление открытого разыменовывает сессию, сцена остаётся).
- **`ProjectAutosave`** — пишет в файл ТЕКУЩЕГО проекта (`ProjectPaths.CurrentSavePath`);
  на старте открывает текущий, при пропаже/порче файла — деградация до безымянного
  автосейва. `Save(path): bool` — «записано ли» (пустая сцена → false).
- **Import стал только про импорт**: строка «New project» уехала в Projects
  (`ImportController.NewProject` остался как API очистки сцены).
- Дальше: «Импорт IFC = новый проект» (опция), переименование (нужен ввод текста),
  экспорт glTF.

### Версии схемы

`1` — стены/полы/лестницы/MEP · `2` — электрика (аудит B1) · `3` — покраска по сторонам
стены (#34) · `4` — мебель каталога (design/27) · **`5`** — материалы импортированных
предметов: `ProjectMep.Parts` (имя материала, цвет, прозрачность, отделка и диапазон
треугольников `TriStart/TriCount`) и `ProjectMep.Uvs` (метрическая box-развёртка),
design/29. Файлы v4 и старше читаются как «одна часть на элемент» — прежний вид;
читатель отказывает только на версии НОВЕЕ своей.

**`6`** — нативная сантехника и трубы: `PlumbingFixtures` и `PipeRoutes` отдельно
от прежнего `Plumbing` (IFC `ProjectMep`). Сохраняются поза, габариты, локальные
порты с подтверждением, система, спецификация трубы, точки и ссылки на концы.
`MountKey` стен/плит и приборов восстанавливает нативные опоры без поиска ближайшей
стены; `ShowDimensions` сохраняет видимость размеров. Старые проекты читаются
без новых коллекций, электрика без ключа остаётся unhosted. Автосейв принимает
и проект, содержащий только нативную сантехнику/трубы.

Два слоя данных:
- **Семантика** (источник истины) — наш **JSON**: комнаты (стены/пол/потолок из
  MRUK-JSON), граф стен, проёмы, отделка (материалы/зоны/UV-привязки), мебель, инженерные
  сети, подложка чертежа + калибровка, метаданные.
- **Меш** — **glTF/glb** для DCC (3ds Max) и рендеров.

Возможности:
- **Снял на объекте → доделал дома** через JSON-сериализацию сцены (MRUK
  `SaveSceneToJson`/`LoadSceneFromJson`); дома редактируем модель, физической привязки к
  месту нет — это ожидаемо.
- **Мульти-рум скан** (по комнатам, `MRUKRoom[]`); сшивка в план этажа — наша логика.
- Кросс-платформенный контейнер `.json` + папка ассетов; облако Meta не обязательно.
- Колокация (несколько человек в одной комнате) — Shared Spatial Anchors / Space Sharing
  (по желанию).

Обмен с CAD/BIM (IFC, DWG, glTF/FBX) — вынесен в [08-interop](08-interop.md).
