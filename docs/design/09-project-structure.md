# 09 — Структура проекта и процесс захвата (корневой) 🔜

С этого всё начинается: как проект устроен и как из скана комнат собирается дом.

## Иерархия данных

```
Project (Дом/Объект)
 └── Floor (Этаж)          — номер, высота этажа (floor-to-floor), Y-смещение
      └── Room (Комната)   — скан (Scene из MRUK) + transform (место на этаже)
           ├── WallGraph        — стены (из скана + виртуальные) → 02-walls
           ├── Surfaces         — отделка → 04-surfaces-materials
           ├── Openings         — двери/окна → 03-openings
           ├── Fixtures/Routes  — мебель + инженерные сети по слоям → 07-mep-layers
           └── captureState     — scanned / partial / empty (можно до-сканировать)
```

**Комната — самостоятельная единица** (свой скан + свой дизайн). Дом = комнаты,
разложенные по этажам с сохранённым взаимным положением. Поэтому дизайн и сканирование
идут **параллельно**: одну комнату уже оформляем, другую ещё не сняли, потом добавляем.

## Процесс (workflow)

1. **Новый проект** (Дом) → задаём этажи и их высоты (напр. 3 этажа × 3 м).
2. **Захват по комнатам:** заходим в комнату → Space Setup → скан → **Ingest** в
   `WallGraph`/поверхности. Помечаем: этаж + имя комнаты.
3. **Сборка** комнат в единый план (см. ниже).
4. **Дизайн:** отделка, стены, проёмы, мебель, инженерка — по комнатам, агрегируется в дом.
5. **Сохранение/до-скан:** JSON (семантика) + glTF; вернуться и дополнить в любой момент.

## Захват: по комнатам (техническая необходимость)

- **Space Setup снимает одну комнату за раз**; MRUK отдаёт `MRUKRoom[]`.
- **В пределах одного этажа** за один непрерывный сеанс трекинга все анкеры в одной
  системе координат → взаимное расположение получается автоматически.
- **«Весь дом одним куском» — ненадёжно:** трекинг Quest непрерывен лишь в разумном
  объёме; между этажами (лестница) копится дрейф. Не основной метод.

## Как правильно сохранить расположение (ключевое)

Собираем комнаты в точный план **независимо от дрейфа**:

- **(а) Авто в пределах сеанса** — комнаты одного непрерывного прохода уже согласованы.
- **(б) Сборка на 2D-плане (базовый надёжный способ)** — вид сверху, таскаем/поворачиваем
  footprint комнат; **snap по общей стене** (стена A|B — одна и та же) и по дверным проёмам.
- **(в) Стыковка по дверям** — соединяем дверь комнаты B с дверью комнаты A → взаимный
  transform (полуавтомат).

**Этажи (вертикаль):** этаж — плоскость комнат; дом — **стек этажей** с параметром высоты
(Y-смещение). Вертикаль задаётся параметром, а не трекингом через лестницу.

Итог: **transform каждой комнаты** (позиция+поворот на этаже) и **Y-этажа** — и есть
«правильно сохранённое расположение». Хранится в проекте, не зависит от того, где стоял шлем.

## Инкрементально и параллельно

- Комнаты независимы → сканируем/оформляем в любом порядке.
- `captureState = partial` — «половина сетки», вернулись и дополнили.
- On-site — скан + работа в реальном MR; дома — грузим JSON и правим виртуально.

## Ingest: Scene → наша модель

Из скана приходит **размеченная семантика** (не облако точек):

| Что даёт MRUK/Scene API | → Наша модель |
|---|---|
| `WALL_FACE` — плоскость (transform + ширина×высота) | концы на полу → `WallNode` × 2 → `WallSegment` |
| контур пола (`FLOOR`, полигон углов) | углы → `WallNode`, рёбра → `WallSegment` (быстрый путь) |
| `CEILING` | высота потолка (магнит для высоты стен) |
| объёмы мебели (`TABLE`/`COUCH`/…) | стартовые элементы слоя Interior |
| `DOOR_FRAME` / `WINDOW_FRAME` | `Opening` на стене |
| Global Mesh (опц.) | сырая сетка для окклюзий/визуала |

Существующие стены **не рисуем руками** — строим `WallGraph` из контура пола/стен-анкеров,
дальше красим, добавляем проёмы и виртуальные перегородки в тот же граф.

Всё — в мировых координатах Unity, привязано к комнате spatial-анкерами (world-locked).
