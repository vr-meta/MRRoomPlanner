# Электрика — аудит и план

Код: `Core/ElectricalTypes.cs`, `Core/WireMath.cs`, `Core/WireRoute.cs`,
`Core/ElectricFixture.cs`, `Core/ElectricalBom.cs`, `Electrical/ElectricController.cs`,
`Electrical/*Parameters.cs`, `Electrical/RouteHandles.cs`.

## Текущее состояние (кратко)

Розетки (1–5 постов) / выключатели (1–3 клавиши) / щиток / распредкоробки; два типа
кабеля (3x1.5 / 3x2.5) с авто-дефолтом от стартовой фикстуры; Ortho (одно колено,
магистраль поверху) / Free; магнит к терминалам 10 см, клик по терминалу = финиш;
смета Σ по типам + 0.15 м/подключение + резерв %; перемещение фикстуры тянет
привязанные концы; ручки изломов; параметры с undo; телепорт двигает электрику
(включая `BaseLevel`).

## Баги к исправлению

### Б1. Электрика не переживает перезапуск (P0/B1 = E9) — главный долг проекта
`ProjectData` про `Fixture`/`WireRoute` не знает, а `ClearScene` при загрузке их
**уничтожает**: импорт здания + разводка + перезапуск = здание вернулось, электрика
исчезла. Бонус-дыра: сцена «только из электрики» вообще не сохраняется
(`ProjectAutosave.Save` требует стен/полов).

**Как должно работать (формат v2, см. [12-persistence.md](12-persistence.md)):**
- `ProjectFixture`: Kind, позиция, поворот (нормаль стены), Posts/Keys, BaseLevel,
  HeightAboveLevel, **Id** (строковый, сохраняется как есть).
- `ProjectWire`: список точек, CableType, StartFixtureId/EndFixtureId.
- Id при загрузке восстанавливаются 1:1 (генератор `_nextId` инициализируется
  максимумом из файла) — связи фикстура↔трасса переживают round-trip.
- Условие «пустая сцена не пишется» учитывает электрику.
- Round-trip-тест: розетка + щиток + трасса → save/load → смета щитка та же.

### Б2. Щиток размножается через undo
`FindPanel()` пропускает скрытые: удалили щиток (скрытие) → поставили второй →
undo воскресил первый → щитков два при инварианте «один на сцену».

**Как должно работать:** `FindPanel` учитывает скрытые (скрытый щиток блокирует
постановку нового; ряд-подсказка «Panel deleted — undo or place elsewhere»), либо
постановка нового щитка **вычищает** скрытый из истории (`PurgeWhere`). Первое
честнее к undo.

### Б3. Висячие id при удалении фикстуры
Удалённая розетка остаётся в `StartFixtureId` трасс → конец считается подключённым
(+0.15 м в смете).

**Как должно работать:** смета и Describe считают конец подключённым только если
фикстура с таким id **жива и не скрыта** (резолв уже происходит через реестр —
добавить проверку `IsAlive && !IsHidden`). Id-ссылку не рвать: undo удаления
восстанавливает связь бесплатно.

## Развитие

### Р1. Undo создания фикстур и трасс (S1)
`FixtureCreateCommand` / `RouteCreateCommand` по общему паттерну (Execute =
показать+зарегистрировать, Undo = скрыть). B-семантика не меняется.

### Р2. Светильники и логические цепи (F5)
Превращает инструмент из «рисовалки» в проектирование.

**Как должно работать:**
- `FixtureKind.Light`: потолочный (тарелка Ø200×40) и настенный (бра) — по нормали
  поверхности; терминал в центре тыльной стороны.
- Суб-таб `Light` (6-й таб; иконка — лампочка в `IconPaths` + тест).
- Логическая цепь: выключатель получает список `ControlsIds` (светильники). Жест:
  триггер по выключателю в режиме Light-таба → режим связывания → триггеры по
  светильникам добавляют/снимают связь (линия-превью цвета слоя), B — конец.
  Связь — данные (`SwitchLink`), персистится, в смете не участвует.
- Проверка цепи: Readout у выключателя «Controls: 3 lights»; у светильника без
  выключателя и без трассы — маркер-warning в Describe.
- v2: примерка света — Toggle «Preview light» у светильника включает реальный
  point light (лимит 4 активных, URP Forward).

### Р3. Экспорт сметы (CSV)
Action «Export BOM» в схеме щитка → `bom-<дата>.csv` в Download: строки по типам
кабеля (длина, запас), список фикстур по типам с количеством, unrouted. Формат —
UTF-8 BOM для Excel. Это первый экспорт наружу вообще — переиспользовать паттерн
для спецификаций комнат.

### Р4. Несколько щитков / группы — v3
Каждой трассе — «домашний» щиток (по связности через коробки); смета щитка считает
только своё дерево. Не раньше реального запроса.

## Техдолг

- `Describe()` щитка и readout `Wires` коробки обходят весь реестр с аллокацией
  списка — при открытом инспекторе это каждый тик. Кэш по версии реестра
  (`SceneModel.Version`), пересчёт только по изменению.
- Связи id → линейный перебор `Items` — обратный индекс `Dictionary<string, List<WireRoute>>`
  в `SceneModel` (пригодится и для Б3, и для Р2).
- `TeleportCommand.CollectFixtures` берёт и ghost-превью (Include inactive без
  фильтра) — фильтровать по регистрации в `SceneModel`.
- Мёртвый API `CeilingOffset*` в `ElectricalTypes` — удалить.
- `OverlapsExistingFixture` сравнивает 3D-расстояние центров без учёта высоты —
  розетка (30 см) и выключатель (90 см) на одной вертикали ложно конфликтуют;
  сравнивать в плоскости стены.
- E8/E10.6 — проверка на устройстве не прогнана.

## Порядок работ

1. Б1 (персист) — первым, в составе формата v2.
2. Б3 (висячие id) + индекс связей.
3. Р1 (undo создания) — вместе с S1; Б2 — тем же заходом.
4. Р3 (CSV) — маленький и показательный.
5. Р2 (светильники) — полноценная фича `/new-feature`, дизайн в `19-electrical.md` → «v3».
