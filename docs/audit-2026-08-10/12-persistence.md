# Персистентность и undo-контракт — аудит и план

Код: `Core/Project/ProjectData.cs`, `Import/ProjectStore.cs`, `Import/ProjectAutosave.cs`,
`Editing/Model/EditHistory.cs`, дизайн `docs/design/06-project-format.md`.

Это **самый крупный сквозной разрыв** проекта: формат v1 честно хранит стены/полы/
лестницы/MEP/план/краску-цвет, но теряет электрику, измерения, текстурные отделки,
этажность; один безымянный файл; сохранение только на pause/quit; неатомарная запись.

## Баги к исправлению

### Б1. Неатомарная запись + молчаливая потеря битого файла (P0/B12)
`File.WriteAllText` напрямую: kill посреди записи = усечённый JSON; битый файл
ловится catch → пустой старт → первый же выход **перезаписывает** файл. Данные
невосстановимы.

**Как должно работать:** запись во временный файл → `File.Replace` (с бэкапом
`autosave.rp.json.bak`); при битом основном — попытка загрузки из `.bak` с
Readout-предупреждением; битый файл переименовывается в `autosave.rp.corrupt-<ts>.json`,
а не перетирается.

### Б2. `Version` не проверяется
Файл новой версии молча прочитается частично. **Как должно работать:** version >
поддерживаемой → отказ загрузки с сообщением; version < текущей → явная миграция
(см. Р1).

## Р1. Формат v2 (S2) — один заход, закрывает четыре потери данных

Состав (сводит требования из профильных доков):

| Секция | Что добавить | Источник |
|---|---|---|
| `Fixtures[]`, `Wires[]` | Kind/позиция/Posts/Keys/BaseLevel/высота/**Id**; точки/кабель/Start/EndFixtureId | [08-electrical.md](08-electrical.md) §Б1 |
| `Measures[]` | пары точек (+`ChainId` под площади) | [01-measure.md](01-measure.md) §Б1 |

| узлы графа по **id** | загрузка без `SnapOrCreateNode` — топология не мутирует | [02-walls.md](02-walls.md) §Б4 |
| `OpenDeg` у проёмов | интерактивные двери | [03-openings.md](03-openings.md) |

Механика миграции: `ProjectData.Version` читается до полного парса; `MigrateV1ToV2`
— чистая функция над DTO (v1-поля получают дефолты: пустая электрика, `Storey=-1`
→ пере-раскладка по отметкам плит), покрыта тестом на реальном v1-файле-фикстуре.
`ClearScene` при загрузке начинает удалять и измерения. Условие «пустая сцена не
пишется» учитывает все новые секции.

## Р2. Мультипроекты (F7)

**Как должно работать:**
- Файлы `<имя>.rp.json` в папке приложения; `autosave.rp.json` остаётся
  «последней сессией».
- В инструменте Import (позже — отдельная страница «Project» с шестерёнки):
  Select «Project» (список через готовый `PlanFileLocator.FindFiles`), Action
  «Open», Action «Save as…» (имя — numpad-транслит недоступен, поэтому v1: авто-имя
  `project-<дата>`, переименование — файловым менеджером; честно задокументировать),
  Action «New project» (уже есть).
- Автосейв пишет в **текущий открытый** файл; смена проекта = автосейв старого →
  загрузка нового.

## Р3. Периодический автосейв

Таймер 3 мин (только при «грязной» истории с последнего сейва — флаг из
`EditHistory`), плюс существующие pause/quit. Запись — Б1-атомарная, в фоне
формирование JSON недоступно (JsonUtility — главный поток), но данные небольшие;
замерить, при фризе — разбить Capture по кадрам.

## С1. Undo-контракт создания (S1) — общий паттерн

Сейчас отменяемы правка/удаление/параметры/телепорт/импорт, но **не создание**
(стены, плиты, дыры, измерения, фикстуры, трассы) — системный разрыв «каждое
изменение — команда».

**Паттерн `CreateCommand<T>`:** контроллер создаёт объект → `History.Record(new
CreateCommand(selectable))`; Undo = скрыть (`SetHidden(true)`, как `DeleteCommand`
наоборот), Redo = показать. `Unregister`/`PurgeWhere` уже чистят команды мёртвых
целей. Для стен — с учётом подавления стыков ([02-walls.md](02-walls.md) §Б3).
Внедрять по подсистемам: стены → плиты/дыры → измерения → электрика (ссылки в
профильных доках).

## Техдолг

- `JsonUtility`: нет словарей/полиморфизма — пока хватает; при появлении
  вариативных секций (v3+) рассмотреть ручной писатель (уже нужен для glTF).
- Запечённые MEP-треугольники в JSON — файл растёт текстовыми float'ами; при
  жалобах на размер — base64-бинарный блок или сжатие (v3).
- История без лимита глубины — кап 200 команд с отбрасыванием хвоста.
- `ICommand.Name` не отображается — задел под history-UI, оставить.

## Порядок работ

1. Б1 (атомарная запись) — маленький и срочный.
2. Р1 (формат v2 + Б2 миграции) — главный заход; профильные Б1 из 01/06/08/09
   закрываются здесь.
3. С1 (undo создания) — следом, по подсистемам.
4. Р3 (периодический автосейв) → Р2 (мультипроекты).
