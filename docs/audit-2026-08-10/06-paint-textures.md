# Покраска, текстуры, рендеринг — аудит и план

Код: `Tools/PaintController.cs`, `Core/SurfaceFinish.cs`, `Editing/FinishLibrary.cs`,
`Editing/Selectable.cs` (`ApplyVisual`), `Editor/TextureDownloader.cs`,
`Shaders/LitVertexAO.shader`, `Core/MeshShading.cs`, `Editor/Setup/SetupCoreRig.cs`,
`Editor/URPSetup.cs`.

## Текущее состояние (кратко)

Paint: табы Color (8 пресетов) / Walls (8 CC0-текстур) / Floors (4), всё через MPB
(материалы не мутируются, красится только submesh 0 — стекло/столярка целы), undo
`PaintCommand`, hover лерпится от краски. Рендер: URP Lit + свой `LitVertexAO`
(ambient × vertex-color, все 4 soft-shadow keyword'а для Quest), Sun+Fill,
vertex-AO двух правил (плинтус/контур), SSAO-фича (выкл по умолчанию), процедурный
бетон, стабильные GUID материалов.

## Баги к исправлению

### Б1. Текстуры не переживают save/load (P0/B2 = T6)
`ProjectData` хранит только `Painted + Color`; текстурный пол после загрузки —
белый цвет (тихая потеря).

**Как должно работать:** в формате v2 у каждого крашеного объекта —
`FinishKind (Color|Texture)`, `TextureId` (строковый id из `FinishLibrary`),
`TileMeters`, `Tint`. `Apply` восстанавливает через `Selectable.SetPaint` с
резолвом id по библиотеке; неизвестный id (текстуры не скачаны) → деградация в
тинт + warning в статус. Round-trip-тест: текстура → save → load → тот же id/tile.

### Б2. «Original look» никогда не срабатывает (P0/B7)
`ClearHovered` работает по `_hover`, но `Tick(blocked)` обнуляет hover, а клик по
ряду инспектора — это как раз `blocked` (`PaintController.cs:164-167, 196`).

**Как должно работать:** вариант A (минимальный): `_hover` не сбрасывать при
blocked, а только подсветку; вариант B (правильный UX): «Original look» — не
Action-ряд, а **9-й свотч** «ластик» (иконка `eraser` уже есть) в каждой странице:
выбранный «ластик» делает триггер по объекту снятием отделки (`PaintCommand` в
`SurfaceFinish.None`). Рекомендуется B — заодно уходит дубль ряда в трёх табах.

### Б3. `Switch To URP` затирает SSAO-фичу (P0/B10)
`URPSetup.SwitchToURP` пересоздаёт `URP-Renderer.asset` по фиксированному пути →
добавленная Setup'ом `ScreenSpaceAmbientOcclusion` теряется, тумблер SSAO молча
мертвеет.

**Как должно работать:** `SwitchToURP` идемпотентен: если ассеты существуют —
не пересоздавать, только донастроить; `EnsureSsaoFeature` вызывается в конце и
там, и в SetupRig. Тест-скрипт CI: SwitchToURP дважды → фича на месте.

### Б4. Верх плиты — только план-UV (T4)
Паркет на верхней грани тайлится масштабом чертежа и вращается с планом; покраска
пола затирает план.

**Как должно работать:** `Floor.TopUvMetric` (bool на экземпляр): при текстурной
отделке верха — метрические UV (1 м), при плане — план-UV. Переключение автоматом:
`SetPaint(Texture)` на плите → `TopUvMetric = true` + Rebuild; «ластик»/план →
обратно. План и отделка на одной плите взаимоисключаются осознанно, пока план не
станет слоем ([07-blueprint.md](07-blueprint.md) §Р1).

### Б5. Таб не проверяет тип цели
Паркет клеится на стену, обои на пол. **Как должно работать:** фильтр по
`Selectable.Kind` против категории свотча (`FinishCategory` уже есть в библиотеке):
несовпадение → ghost/ретикл Danger, триггер даёт отказ-хаптику. Цвета (таб Color) —
на всё, как сейчас.

## Развитие

### Р1. Отделка по сторонам стены
Сейчас красится объект целиком — «обои внутри, краска снаружи» невозможны, хотя
панелизация уже раздельно строит стороны.

**Как должно работать:** submesh тела стены делится на `Side A | Side B | торцы/верх`
(3 сабмеша тела + стекло + столярка = 5). `SurfaceFinish` у стены становится парой
(A/B; торцы наследуют B — внешнюю). Пик запоминает **которой стороной** попал
(знак скалярного произведения нормали хита и нормали стороны) → `PaintCommand`
красит одну сторону. Персист: два финиша в `ProjectWall`. Плата: +2 слота MPB,
рост draw calls — измерить на Quest (см. Техдолг про SRP-батчинг).

### Р2. Покраска комнаты (после комнат, [02-walls.md](02-walls.md) §Р4)
Action «Paint room» при активном свотче: все внутренние стороны стен кольца комнаты
одной командой-батчем (список `PaintCommand` в одном `ICommand`).

### Р3. Тинт и tile за поверхность
Per-instance ряды у выбранного крашеного объекта: Swatch `Tint` (та же палитра)
и Numeric `Tile` (0.25…5 м) → поля уже в `SurfaceFinish`, нет только UI.

### Р4. Потолки в Paint — категория Ceilings после [02-walls.md](02-walls.md) §Р5.

## Техдолг / рендер-риски

- **SRP-батчинг:** MPB c `_BaseMap_ST` выбивает объект из батча → каждая крашеная
  поверхность = draw call. При жалобах на fps: перейти на массив материалов-вариантов
  из `FinishLibrary` (один материал на текстуру, шаринг между объектами) вместо MPB
  для текстур; тинт оставить в MPB.
- `Selectable.Resolve()` кэширует рендереры один раз — при пересборке меша/смене
  сабмешей (Р1!) кэш протухает. Добавить `Selectable.Invalidate()` и звать из
  Rebuild-путей.
- `ToggleVertexAO` пересобирает только стены/полы/лестницы — задокументировать
  (импорт/MEP на PlainLit без vertex-color, это осознанно).
- `LitVertexAO` добавить в `m_AlwaysIncludedShaders` — иначе стриппинг билда может
  молча дать белые поверхности.
- SSAO AfterOpaque ложится и на непрозрачные UI-плашки — проверить на устройстве;
  если затемняет, UI-материалы переводить в Transparent queue.
- `TextureDownloader.AllPresent()` не вызывается — сделать честную ошибку SetupRig
  при неполном наборе (обещано в `04-surfaces-materials.md`).
- `_palette` static в `PaintController` — убрать static.
- Смешение «цвет из IFC» и «краска пользователя» — при формате v2 пометить
  источник (`FinishSource: Ifc|User`), чтобы «ластик» мог возвращать к IFC-цвету,
  а не к бетону.

## Порядок работ

1. Б1 (персист) — в составе формата v2; Б4 (TopUvMetric) — сразу за ним (оба в
   чек-листе как T6/T4).
2. Б2 (ластик-свотч) + Б5 (фильтр таба) — один UX-заход по Paint.
3. Б3 (идемпотентный URP-сетап).
4. Р1 (стороны стен) — отдельная фича `/new-feature` с замером перфа.
5. Р3 (тинт/tile) → Р2 (комната) → Р4 (потолки).
