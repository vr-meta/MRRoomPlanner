# Blueprint (чертёж на полу) — аудит и план

Код: `Core/BlueprintMath.cs`, `Floors/BlueprintController.cs`, `Core/PlanFileLocator.cs`,
`Editor/Setup/SetupBlueprintTool.cs`.

## Текущее состояние (кратко)

Масштаб (слайдер 0.5…50 м) / поворот / сдвиг стиком с живой пересборкой плит;
калибровка по 2 точкам (`FromPointPairs` — масштаб+поворот+смещение одним действием);
выбор файла из Download/Pictures/папки приложения (свежие сверху, кап 20); placement
персистится. Эталонная модульность: всё состояние в инструменте.

## Баги к исправлению

### Б1. Калибровка без клампа и с порогом 1 мм (P0/B9)
`FromPointPairs` пишется в `planScale` без клампа 0.5…50 (`BlueprintController.cs:192-195`),
порог вырожденности `MinSegment = 1e-3` (дизайн требует ~10 см). Короткая база →
масштаб вне диапазона, слайдер врёт.

**Как должно работать:** результат калибровки клампится теми же границами, что
слайдер и `SetPlacement`; при клампе — Danger-хаптика и Readout «Calibration out of
range». `MinSegment` = 0.1 м для **комнатных** точек (пары «на плане» оставляют
1 мм — там масштаб другой). Тест: база 5 см → калибровка отклонена, placement
не изменился.

### Б2. Правки плана вне истории команд
Масштаб/поворот/сдвиг/калибровка меняют поля напрямую — единственный инструмент,
целиком игнорирующий undo-контракт.

**Как должно работать:** `PlanPlacementCommand` (before/after весь
`BlueprintPlacement`): слайдер — одна команда на драг (preview/commit уже разделены
схемой), степпер поворота — команда на клик, стик-сдвиг — команда на «жест»
(отпустил стик > 0.3 с = коммит), калибровка — одна команда на все 4 точки.

## Развитие

### Р1. План как отдельный слой (главное архитектурное)
Сейчас план — текстура общего материала `Floor_Top`: один лист на все плиты и
этажи, конфликт с отделкой пола, бетон и чертёж не сосуществуют.

**Как должно работать:** отвязать от материала пола. `PlanOverlay` — тонкий quad
(или decal-проекция) на 2 мм выше верхней грани каждой плиты **своего этажа**,
с собственным материалом (Unlit, полупрозрачный), обрезка по контуру плиты — меш
оверлея генерируется из той же триангуляции верха. Тогда: (а) лист привязывается
к этажу (`StoreyLevel` в placement); (б) отделка пола живёт под планом; (в)
появляется Slider «Opacity» 0…100 %. Плиты перестают пересобираться при сдвиге
плана — двигается только оверлей (перф-бонус: сейчас каждый тик стика = ребилд
всех плит).

### Р2. Файл плана в проект
Путь не сохраняется — после загрузки проекта план выбирать заново.

**Как должно работать:** в placement-секции формата v2 — имя файла (без пути) +
все каталоги `PlanFileLocator` как область поиска при загрузке; не нашёлся —
Readout «plan file missing: <имя>», placement сохраняется.

### Р3. Несколько листов (по этажу) — после Р1
Список placement'ов (лист × этаж); ряд Select «Storey» в схеме Plan. Не раньше
реального второго этажа в использовании.

### Р4. Визуализация калибровки
Поставленные точки не видны. **Как должно работать:** маркеры A′/A/B′ (стиль
маркеров рулетки, цвет слоя Blueprint) + линия текущей пары; после 4-й точки
маркеры гаснут. B во время калибровки снимает последнюю точку, не всю калибровку.

## Техдолг

- `ReloadPlan` пишет текстуру в материал-**ассет** (`Floor_Top.mat`) — в Editor
  грязнит репозиторий. Уйдёт само при Р1; до того — писать через MPB плит.
- `wrapMode = Clamp` растягивает крайние пиксели за границами листа — после Р1
  оверлей просто обрезается по размеру листа (UV вне [0,1] → discard/alpha 0).
- Мёртвые `NextFile()`/`SelectedFileLabel()` (и дубль в `ImportController`) — удалить.
- Гонка индекса файла (список пересканируется при открытии, выбор по индексу) —
  хранить выбранное **имя**, не индекс.

## Порядок работ

1. Б1 (кламп калибровки) — маленький фикс с тестом.
2. Б2 (undo) — вместе с S1.
3. Р2 (файл в проект) — вместе с форматом v2.
4. Р1 (слой) — отдельная фича; Р4 — внутри неё; Р3 — по запросу.
