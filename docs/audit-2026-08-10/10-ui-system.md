## Текущее состояние (кратко)

Радиал 12 слотов (8 занято, 4 резервных) с гистерезисом/фликом, целиком
процедурный; 12 типов виджетов с preview/commit; попапы (Select-список, numpad,
свотчи) с честной модальностью; летающая панель снапов с грип-парковкой; тултипы,
авторепит, destructive-hold; 47 SVG-иконок с тесселяцией и тестами.

## Баги / достройка обязательного

### Б1. Numpad без десятичной точки
Дробные значения вводятся только через `DisplayScale` (см) — Level в метрах с
дробью не ввести. **Как должно работать:** клавиша `.` вместо `±` (знак — по
long-press на `.` или отдельной раскладкой при Min<0); парсинг
`InvariantCulture`; запрет второй точки; тесты на парсинг/кламп (у `UiPopups`
сейчас 0 тестов).

### Б2. Readout-ряды не обновляются
`RefreshValues()` — только по событиям; живой статус («Wires: N», статус импорта)
врёт до следующего клика. **Как должно работать:** таймер 0.5 с в `InspectorPanel`
обновляет только Readout/Progress-ряды (без пересборки); Readout-делегаты обязаны
быть дешёвыми — см. кэш сметы в [08-electrical.md](08-electrical.md) §Техдолг.

### Б3. Панель без скролла
Длинная схема упирается в физический габарит. **Как должно работать:** максимум
высоты ~0.42 м; при переполнении — скролл правым стиком (паттерн Select-списка),
тонкий индикатор-полоска справа. Popап-скролл уже написан — переиспользовать.

### Б4. Шестерёнка не показывает состояние
Страница Rendering открыта — кнопка выглядит неактивной. Сделать её `Toggle`-видом
(LED), состояние из `_showRenderSettings`.

## Развитие

### Р1. Кнопки Undo/Redo на панель снапов
Иконки `undo`/`redo` нарисованы, кнопок нет; X/Y работают, но не видны и не
дискаверабельны. Ряд 1 панели: + две Momentary-кнопки (после gear), disabled-состояние
от `History.CanUndo/CanRedo` — первое живое применение `SetEnabled`.

### Р2. Подключить Progress к импорту IFC — см. [09-ifc-import.md](09-ifc-import.md) §Р1.

### Р3. Токены-сироты: подключить или удалить
~10 анимационных токенов (`HoverInSeconds`, `PanelFadeSeconds`,
`TooltipDelaySeconds`, `PostCloseDebounceSeconds`…) не читаются нигде; дебаунс
захардкожен `0.15f`; `UiColors` — второй источник правды (у `MenuButton` своя
`DisabledLabelAlpha=0.25` против `UiTokens.DisabledAlpha=0.40`).

**Решение:** захардкоженные тайминги в `ToolManager` заменить на токены (дебаунс,
авторепит); `TooltipDelaySeconds` подключить к тултипам (сейчас мгновенно —
мигает при скольжении); fade-токены либо реализовать (альфа-лерп панелей при
спавне/переезде — дёшево), либо удалить из `UiTokens` с пометкой в доке 20;
`UiColors` — deprecated-алиас, `MenuButton` перевести на `UiTokens`.

### Р4. Мёртвые типы виджетов
`Cycle` — 0 использований в инструментах (запрещён дизайн-кодом) → удалить рендерер
и тип, тесты перевести. `Progress` оживает в Р2.

### Р5. Радиал: резервные слоты со смыслом
Резервные секторы — серая точка без объяснения. Дать им иконку (уже есть) в 25 %
альфы + тултип «Openings — coming soon» при наведении лучом; невыбираемость
сохраняется. Слот 4 оживёт инструментом Openings ([03-openings.md](03-openings.md)).
Плюс мелочь: `RaySlot` не ограничен дистанцией — добавить лимит 1.2 м как у панелей.

### Р6. Заголовок инспектора = имя инструмента
Статичный title (`SetupInspector`) → «Wall settings» / «Paint» из
`ITool.PaletteLabel` при ребинде схемы.

## Техдолг

- `ToolManager.Update()` ~280 строк, ~10 полей состояния модальностей — вынести
  роутинг в явную цепочку `IInputLayer` (радиал → попап → слайдер → грип → телепорт
  → инструмент → кнопки); появится точка для тестов роутинга (сейчас 0).
- `SetScan` перебирает все MonoBehaviour сцены (4 раза на старте) и матчит MRUK по
  имени типа — кэшировать найденное, инвалидация по спавну скана (событие MRUK).
- Попапы пересоздают меши на каждое открытие — общий `_plateCache` c
  `InspectorPanel`.
- `MenuButton` не самодостаточна вне палитры (hold/repeat живут в `ToolManager`) —
  при первом же попапе с репитом вынести таймеры в кнопку.
- Радиал: мёртвый `WithAlpha`, undo/redo «сквозь» открытый радиал (X/Y не гейтятся) —
  гейтить.
- Нет тестов: `UiPopups` (numpad!), роутинг `ToolManager`, `MeasureInput`.

## Порядок работ

1. Б1 (точка) + Б2 (Readout) + Б4 (gear) — один UX-заход.
2. Р1 (Undo/Redo кнопки) + Р5 (тултипы резервных слотов).
3. Б3 (скролл) — до первого длинного инструмента (Openings добавит рядов).
4. Р3/Р4 (токены, мёртвые типы) — гигиена без риска.
5. Техдолг `IInputLayer` — перед следующей модальностью ввода.
