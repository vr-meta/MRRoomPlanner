# Лестницы (Stair) — аудит и план

Код: `Core/Stair.cs` (namespace `RoomPlanner.Stairs`), импорт — `Core/Ifc/IfcImporter.cs`
(`ImportStairs`, `NormalizeStairSize`), персист — `ProjectStair`.

## Текущее состояние (кратко)

Качественный параметрический модуль: марш по `Base/YawDeg/Width/Risers/RiserHeight/
TreadDepth`, три конструктивных типа (`Solid` монолит / `Open` косоуры / `Waist`
марш-плита с наклонным софитом), универсальная экструзия профиля `Prism`, метрические
UV, vertex-AO, клампы, тесты геометрии. Импорт из IFC (включая нормализацию футов
Revit), персист с легаси-флагом, покраска, телепорт по ступеням.

**Главное:** всё это доступно **только через импорт**. Инструмента нет, у выбранной
лестницы ноль строк параметров в инспекторе, ручек нет, правки не отменяемы.

## Развитие (по возрастанию стоимости)

### Р1. `StairParameters : ISettingsProvider` — параметры за экземпляр
Самый дешёвый шаг: API весь есть (`Rebuild`, `SetKind`).
- Ряды: Numeric `Steps` (Risers, 2…30), Numeric `Riser` (см, 12…20 дефолт-диапазон
  подсветкой, кламп шире), Numeric `Tread` (см), Numeric `Width` (см), Segmented
  `Kind: Solid | Open | Waist`, Readout `Total: H 2.72 m · run 3.00 m`.
- Все правки — `StairParamCommand` before/after (по образцу `FloorParamCommand`);
  пересборка меша на коммит, коллайдер один раз.
- Selection-блок уже показывает «N steps, H cm up» — оставить.

### Р2. Ручка поворота (Yaw)
Одна ручка на верхней ступени по оси марша: драг по дуге вокруг `Base` (проекция
луча на плоскость уровня → атан) с угловым снапом 15° при включённом Angle;
`StairYawCommand` на жест. Позже — вторая ручка длины (тянет `Risers` при
фиксированном `RiserHeight`, дискретно по ступеням).

### Р3. Инструмент «Stairs»
Слот в радиале не зарезервирован (12 слотов зафиксированы) → по правилам дизайн-кода
UI новые инструменты — в резервные слоты или **табом**. Лестница — вертикальная
конструкция между этажами: логично жить **табом в инструменте Wall** нельзя —
семантика чужая; правильнее занять один из резервных слотов не-MEP (слот 5
«Furniture» не трогаем — зарезервирован под AI). Решение: лестница = **суб-таб
инструмента Floor** (Tabs: `Slab | Stairs`) — оба строят горизонтально-привязанную
конструкцию от Level, и иконка `stairs` уже есть в `IconPaths`.

Постановка (два клика):
1. Триггер в точку **низа** марша (на плите/уровне) — фиксируется `Base`;
   превью-ghost марша тянется за лучом.
2. Драг/второй клик задаёт направление (Yaw из XZ-вектора, снап 15°) и — если
   целимся в верхнюю плиту/уровень — высоту: `Risers = ceil(ΔY / RiserHeight)`,
   `RiserHeight = ΔY / Risers` (точная посадка на этаж). Если цели нет — высота из
   дефолтов схемы.
- Схема инструмента: дефолты Steps/Riser/Tread/Width/Kind (те же ряды, что Р1).
- `StairCreateCommand` (undo), регистрация в `SceneModel`.

### Р4. Связка с перекрытием — авто-проём
После Р3: если марш упирается в существующую плиту верхнего уровня, предложить
дыру под марш: Action «Cut opening above» в per-instance схеме → прямоугольное
кольцо (Width + 10 см запас × проекция верхних ступеней) через
`FloorHoleCommand` ([04-floors.md](04-floors.md) §Р1). Не автоматически — плита
могла быть нужна целой.

### Р5. Не делаем (пока)
Забежные/винтовые марши, площадки как часть лестницы (площадка = плита, работает),
перила как параметрика (импортируются MEP-мешами), nosing, отдельный материал
подступенков. Вернуться после реального использования Р1–Р3.

## Техдолг

- Пересборка без `DeferCollider` — при появлении ручек (Р2) обязателен порт
  отложенного коллайдера, иначе драг Yaw = перепечка коллайдера каждый кадр.
- `Prism` аллоцирует списки на каждую перестройку (у Open — `Risers−1` призм) —
  буферы.
- Зависимость Core `Stair` → `RoomPlanner.Floors.Floor` ради одной константы
  `TileMeters` — вынести константу в общий `SurfaceConstants`.
- Соглашение «профиль обходится вверх по левой кромке» держится на комментарии —
  добавить debug-assert по знаковой площади профиля.
- Двойное поле типа в персисте (`Open` bool + `Kind` int) — при формате v2 оставить
  только `Kind` с миграцией.
