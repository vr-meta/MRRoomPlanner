# Ненача́тые направления — что строить дальше

Направления из `ARCHITECTURE.md`, у которых в коде нет ни строчки (или почти).
Порядок — рекомендуемый: каждое опирается на предыдущую инфраструктуру.

## 1. AI Placement — мебель по описанию (слот 5 радиала)

Дизайн-основа: `docs/design/05-ai-placement.md`. Зарезервированы слот радиала и
иконка `furniture`.

**Как должно работать (v1, без сети из шлема — через файл):**
- Этап 0 — **каталог примитивов**: инструмент «Furn» ставит параметрические
  коробки-плейсхолдеры (кровать 1600×2000×450, стол, шкаф, диван — ~10 пресетов
  из Select-списка), с поворотом ручкой Yaw, снапом к стенам (спинка к стене),
  undo, персистом. Это полезно само по себе (планировка расстановки) и не требует
  AI вовсе.
- Этап 1 — **AI-раскладка**: запрос («спальня на двоих с рабочим местом») →
  Claude structured output → список `{preset, position, rotation}` в координатах
  комнаты (контур комнаты из [02-walls.md](02-walls.md) §Р4 — обязательная
  зависимость). Транспорт v1: сопутствующее десктоп/веб-приложение или
  `adb push` JSON в папку приложения; в шлеме — «Load layout». Прямой HTTP из
  приложения — этап 2 (ключи, приватность).
- Этап 2 — замена примитивов на glTF-модели каталога (нужен glTF-**ридер**;
  писатель уже будет из [09-ifc-import.md](09-ifc-import.md) §Р2 — часть кода общая).

## 2. Отопление и сантехника (слоты 9–10 радиала)

Дизайн-основа: `docs/design/07-mep-layers.md`; иконки `radiator`/`pipe` готовы;
электрика v1 — отработанный образец (типы → математика труб → вью → контроллер с
табами → BOM).

**Как должно работать (v1 отопления):** радиаторы (параметрический бокс по
секциям, под окном — снап к центру проёма после [03-openings.md](03-openings.md)),
трубы Ø20 парой (подача/обратка) той же `WireMath`-механикой (Ortho вдоль пола),
BOM метража труб. Сантехника: трапы/точки подключения + трубы Ø50/110 с уклоном
2 % (валидация уклона — то, чего электрике не требовалось). Слой = цвет из
резерва `UiTokens`. Начинать после светильников ([08-electrical.md](08-electrical.md)
§Р2), чтобы обкатать паттерн «логических связей» на электрике.

## 3. Ingest скана: MRUK → WallGraph (раздел 4 чек-листа)

Сейчас скан — декорация: по нему можно мерить и на него ставить, но он не
редактируется и не персистится.

**Как должно работать:** Action «Trace scan» в Import (или Wall): грани
`WALL_FACE` из MRUK → пары встречных параллельных граней → сегмент + толщина
(медиальная ось, пороги из чек-листа §4); периметр-одиночки → толщина наружу;
`DOOR_FRAME`/`WINDOW_FRAME` → `WallOpening`; контур пола → плита. Результат —
один `ImportBatchCommand` (переиспользуем путь IFC-импорта целиком). Автотест из
чек-листа: повторная экструзия воспроизводит скан. Это превращает «скан → своя
редактируемая модель» в одну кнопку — главная киллер-фича для реальных квартир.

## 4. Hand tracking

В коде нет ни `OVRHand`, ни скелета (только манифест). Вводный слой уже
абстрагирован (`MeasureInput`/`PointerProvider`), так что вход дешевле, чем
кажется, но: пинч вместо триггера, луч от кисти, отсутствие грипа/стиков (снапы,
глубина, ход) требуют отдельной раскладки жестов. **Решение: не начинать**, пока
контроллерный UX не пройдёт полные проверки на устройстве (открытые L5/E8/P6/I*);
затем — прототип только для Measure Hands-режима (он идеологически ближе всего
к рукам).

## 5. Экспорт/обмен — см. [09-ifc-import.md](09-ifc-import.md) §Р2/Р4
glTF-экспорт → IFC-экспорт → (по запросу) DXF. Плюс 2D: план этажа в PNG/PDF из
`WallGraph` (топ-вью с размерами) — дёшев после комнат и очень презентабелен;
кандидат в тот же заход, что glTF.

## Сводный порядок стратегических работ

1. **Комнаты** ([02](02-walls.md) §Р4) — открывают потолки, покраску комнат,
   спецификации, AI-контекст.
2. **glTF-экспорт + план в PNG** — выход наружу, демо-ценность.
3. **Каталог мебели-примитивов** (AI этап 0).
4. **Ingest скана** — киллер-фича реальных квартир.
5. **AI-раскладка** (этап 1) → glTF-модели (этап 2).
6. **Отопление/сантехника** — после светильников.
7. **Hand tracking** — последним, после стабилизации контроллерного UX.
