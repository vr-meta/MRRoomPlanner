# Архитектура и дорожная карта

## Принцип

Тяжёлое (понимание пространства) даёт платформа Horizon OS: **Space Setup** строит
Scene Model, **Scene API / MRUK** отдают размеченную геометрию (стены/пол/потолок/
мебель) и raycast по ней, **Depth API** — окклюзии, **Passthrough** — фон реального
мира. Мы строим поверх этого прикладную логику интерьерного планировщика.

Базой служит официальный сэмпл **Virtual Home** (room reskinning на EffectMesh).

> 📐 Детальные проектные решения по каждому модулю (модель данных, подход, UX) —
> в [`docs/design/`](docs/design/README.md) (по документу на модуль). Этот файл —
> верхнеуровневая карта.

## Слои приложения (целевые)

1. **Scene Provider** — инициализация MRUK, загрузка/запуск Space Setup, доступ к
   анкерам комнаты. (даёт Virtual Home)
2. **Surface Manager** — выбор конкретной поверхности через raycast, назначение
   материала/цвета/текстуры.
3. **Material Library** — палитра красок + текстуры (обои/плитка/паркет) с корректным
   метрическим масштабом (Metric UV, повтор 1 м).
4. **Wall Builder** — рисование виртуальных перегородок по полу, генерация меша.
5. **Blueprint Layer** — подложка чертежа на пол + калибровка (2 точки → масштаб/поворот).
6. **Measure Tools** — рулетка, уровень, редактирование размеров в см. ← **ТЕКУЩИЙ ЭТАП**
7. **AI Placement** — расстановка мебели по описанию через Claude (structured output),
   примитивы-коробки → замена на glTF-модели из каталога.
8. **Project I/O** — сохранение/загрузка проекта (свой JSON) + экспорт геометрии в glTF.
9. **MEP + слои** — система переключаемых слоёв (интерьер / электрика / отопление /
   сантехника / чертёж) + инженерные сети: розетки/выключатели/свет, радиаторы и тёплый
   пол, трапы и трубы; трассы сплайнами; расчёт метража (кабель/трубы) и смета.
   🧭 на будущее. См. `docs/design/07-mep-layers.md`.

## Ключевой принцип

Всё геометрическое и отделочное — **параметрические данные**, меши и материалы
**генерируем процедурно**. Никаких булевых операций (CSG) над готовыми мешами и
«запечённых» развёрток: параметры остаются редактируемыми, поддерживают Undo/Redo,
точный числовой ввод и сохранение в кросс-платформенный формат. Подробности — в
`docs/design/00-overview.md`.

## Этап 1 — Рулетка (реализовано в скелете)

Поток данных:

```
PointerProvider.GetRay()  ──►  SceneRaycaster.TryRaycast()  ──►  точка на поверхности
                                        │
MeasureInput (триггер) ─────────────────┘
                                        ▼
                              MeasureController (A → B)
                                        ▼
                        Measurement (LineRenderer + маркеры + подпись)
                                        ▼
                       MeasurementLabel (форматирование м/см, billboard)
```

Зависимости намеренно развязаны:
- **SceneRaycaster** сейчас использует `Physics.Raycast` по коллайдерам EffectMesh —
  это не зависит от версии MRUK API. Позже можно заменить на `MRUKRoom.Raycast` или
  `EnvironmentRaycastManager` (Depth API) для попадания по произвольным точкам, не
  входящим в Scene Model.
- **PointerProvider / MeasureInput** абстрагируют ввод — легко перейти с контроллеров
  на hand tracking (pinch) без правки логики измерений.
